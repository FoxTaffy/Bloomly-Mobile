# Bloomly Mobile: правила для ИИ-ассистента

Мобильный клиент соцсети Bloomly: Expo 58, React Native 0.88, TypeScript strict, Expo Router, NativeWind 4, TanStack Query, zustand.
Платформы: **iOS, Android, Google Pixel** (Android 15+ рисует edge-to-edge). Язык интерфейса и ответов — русский.
Бэкенд и веб — в отдельном репозитории (`bloomly.fun`), здесь их нет. API: `https://bloomly.fun/api`
(локально `EXPO_PUBLIC_API_URL`).

## Прочитай перед работой
1. `docs/ARCHITECTURE.md` — структура, платформы, стили, авторизация, карта экранов «веб → мобайл», приоритеты P0–P2, открытые вопросы.
2. `GUIDE.md` — запуск и команды. `docs/brand-guide.jpg` — бренд-гайд. `tailwind.config.js` — токены цветов и шрифтов.

## Жёсткие правила
1. **Структура:** экраны только в `app/` (без axios и бизнес-логики); запросы в `src/api`; данные через TanStack Query в `src/hooks`;
   zustand только для клиентского состояния; общие примитивы в `src/components/ui`; алиас импорта `@/` = `src/`.
2. **Цвета и стили:** только классы `brand-*` из `tailwind.config.js`. Цвет в TS-коде — только `colors` из `src/theme/tokens.ts`
   (единственный файл, где разрешены hex). Запрещены `#hex`, `rgb()`, цвета вне палитры бренд-гайда.
   Повторяющийся блок (2+ раза) — компонент в `components/ui`, а не копия цепочки классов. Произвольные значения `[13px]` — только если нет шкалы Tailwind.
3. **Шрифт Nunito:** `font-nunito`, `font-nunito-medium`, `font-nunito-bold`. `font-bold` и `fontWeight` в RN не работают с этим шрифтом.
4. **Платформы:** каждый экран в `<Screen>` или с `useSafeAreaInsets`. Никаких констант высоты статус-бара, выреза, жестовой панели,
   `SafeAreaView` из `react-native`. Раскладка зависит от `useWindowClass()` (compact / medium / expanded), а не от `Platform.OS`.
   `Platform.OS` — только для реально разного поведения и с комментарием. Клавиатура не должна перекрывать поля. Учитывай жест «назад» на Android.
5. **Безопасность:** refresh-токен только в SecureStore, access-токен только в памяти. Только https. Не логировать токены и персональные данные.
   Не использовать веб-API (`localStorage`, `window`, `document`).
6. **Паритет с вебом:** логику не придумывать, переносить из веб-аналога (путь указан в таблице `docs/ARCHITECTURE.md` и в комментарии заглушки экрана).
   Обязательные состояния: загрузка, пусто, ошибка, 18+/NSFW, замороженный аккаунт, режим обслуживания.
   Shop (стикеры и рамки) и Dealers' Den — разные разделы, не смешивать. Новых денежных операций не добавлять.
7. **Зависимости:** только `npx expo install <пакет>`, совместимые с SDK 58 и New Architecture. Не добавлять нативный код без причины. Не удалять `.npmrc` (`legacy-peer-deps`).
8. **Не трогать без прямой просьбы:** `babel.config.js`, `metro.config.js`, `app.json` (bundle id/package `app.bloomly.mobile`, схема `bloomly`), `package-lock.json` вручную.

## Проверка (обязательна перед каждым коммитом)
```
npm run check     # tsc --noEmit + scripts/check-rules.mjs (хардкод цветов, SafeAreaView, веб-API, токены, http)
```
Красная проверка — не коммитить. Скрипт не ловит всё: пройди чек-лист платформ (правило 4) вручную, а новый экран проверь
на узком телефоне (compact), с вырезом/жестовой панелью (Pixel) и на широком окне (Pixel Fold / iPad).

## Порядок работы над экраном
1. Найти веб-аналог в таблице, прочитать его логику.
2. Типы и запросы в `src/api/<домен>.ts`, хук данных в `src/hooks`.
3. Собрать из `components/ui`; нужного примитива нет и он повторится — сначала добавить примитив.
4. `npm run check`, затем коммит.

## Git и границы
Работай в ветке, не в `main`. Коммиты маленькие, сообщения по-русски (`feat(mobile): …`, `fix(mobile): …`).
Не пушить, не делать force-push и не запускать EAS-сборки без явной просьбы. Не коммитить `.env`, ключи, `ios/`, `android/`.
Если правило мешает задаче или требуется новый стиль/зависимость — сказать об этом одной строкой и ждать решения, а не обходить правило.
Открытые вопросы (ассеты иконки, оплата в сторах, рейтинг 18+, EAS, universal links) не решать самому, они в `docs/ARCHITECTURE.md`.
