# Google Play: раздел «Безопасность данных» (черновик)

Основа: что приложение **реально** собирает или отправляет (проверено по коду `app/`, `src/`, `app.json`, `package.json`). Приложение отправляет данные только на собственный сервер (`https://bloomly.fun/api`, WebSocket `/api/`) и в службу push Expo. Сторонних SDK аналитики и рекламы нет. SDK отчётов о сбоях (Sentry) есть в сборке, но **выключен, пока при сборке не задан `EXPO_PUBLIC_SENTRY_DSN`**; ниже указано, что собирается, когда он включён. Если сборка уходит в магазин с DSN, ответы про сбои обязательны; без DSN можно ответить «нет».

Сквозные ответы: данные шифруются при передаче — **да** (только HTTPS/WSS); пользователь может запросить удаление — **да** (в приложении: Настройки → Удалить аккаунт); данные передаются третьим сторонам для рекламы — **нет**; обязательные для работы данные обозначены ниже.

Приложение отправляет с каждым запросом `X-Device-Id`: случайный uuid, созданный при первом запуске и хранящийся в защищённом хранилище устройства (SecureStore/Keychain), он не связан с рекламным идентификатором и сохраняется после выхода из аккаунта. Сервер записывает в сессию (refresh-токен) этот идентификатор, название устройства (из User-Agent) и IP-адрес для безопасности входа и уведомлений о новом устройстве. В форме Play это «Идентификаторы устройства или другие» (цель: функциональность приложения, безопасность) и «IP-адрес» как автоматически собираемые сервером данные: сверить формулировку с политикой конфиденциальности.

## Мониторинг ошибок (Sentry): что именно уходит, когда включён

- Без привязки к человеку: пользователь не задаётся (`setUser` не вызывается), `sendDefaultPii: false`, из события удаляются `user`, `request` (заголовки, cookie, тело), `extra`, имя сервера.
- Тексты ошибок и хлебные крошки очищаются: токены (`Bearer`, JWT), push-токены, адреса почты и uuid заменяются заглушками; крошки консоли и ввода пользователя отбрасываются, сетевые — только метод, статус и путь без параметров. Текстов сообщений, постов и комментариев в событиях нет.
- Не отправляются: трассировки производительности (`tracesSampleRate: 0`), сессии релиза, скриншоты и иерархия экранов.
- Устройство: модель, ОС и версия приложения Sentry добавляет сам (диагностика).
- **В настройках проекта Sentry включить «Prevent Storing of IP Addresses»**: иначе сервер Sentry может сохранить IP отправителя по соединению. Регион хранения данных выбрать при создании проекта (EU или US) и отразить в политике.
- Нативная часть SDK подключается при сборке независимо от DSN; без DSN она ничего не отправляет.

## Хранится только на устройстве (не отправляется)

- Токены: refresh-токен и uuid устройства в защищённом хранилище (SecureStore/Keychain), access-токен только в памяти.
- Настройки: язык и режим NSFW в AsyncStorage.
- Кэш для чтения без сети: первая страница публичной ленты «Для вас» (только публичные посты без 18+ и без «только для подписчиков», без оценок читателя), срок 3 суток, стирается при выходе из аккаунта. Личные сообщения, уведомления и профиль в кэш не пишутся.

## Не собираются

Геолокация (точная и примерная), контакты, календарь, SMS и журнал вызовов, файлы и документы, данные о здоровье и спорте, финансовая информация и платежи (в версии 1.0 платежей нет), история поиска и просмотров вне приложения, рекламный идентификатор, биометрия, отчёты о сбоях без DSN (см. выше).

## Требует внимания до отправки

- Галерея и камера используются только при создании поста: фото и видео из галереи, фото с камеры. Выбранные файлы загружаются на сервер и становятся контентом поста. Микрофон камерой не запрашивается (видео снимать нельзя), микрофон нужен только голосовым сообщениям. Разрешение на фото и камеру по запросу системы; в Play отметить «Фото и видео» как собираемые (необязательные, функциональность приложения, привязаны к аккаунту).
- Политика конфиденциальности: https://bloomly.fun/privacy (содержит плейсхолдер почтового адреса компании, см. REVIEW.md).
